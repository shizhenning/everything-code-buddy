# 实施计划: 黄金矿工游戏 - 总计划

## 概述
本项目旨在构建一个基于 Spring Boot 和 React/Phaser 的黄金矿工互动营销游戏。系统采用"客户端预测 + 服务端验证"架构以确保公平性。项目将拆分为 6 个子计划,涵盖基础设施、后端核心、前端核心、业务功能、安全与测试。

## 项目背景
- **类型**: 本地内网专用的互动营销游戏平台
- **技术栈**:
  - 后端: Java 17 + Spring Boot 3.2 + PostgreSQL 14 + Redis 7
  - 前端: React 18 + TypeScript + Phaser 3 + Vite
  - 部署: Docker Compose 单机编排
- **架构模式**: 客户端预测 + 服务端验证 (防作弊)
- **核心特性**: 钩子物理模拟、积分经济系统、奖品兑换、数据统计分析

## 需求摘要
- **核心玩法**: 钩子摆动、发射、抓取物理模拟、关卡进度系统
- **配置管理**: 钩子速度、宝物配置、关卡配置、等级规则 (支持热更新)
- **用户系统**: 用户参与、关卡进度、游戏记录
- **积分系统**: 积分账户、积分明细、积分排行榜
- **奖品系统**: 奖品配置、库存管理、兑换记录
- **数据分析**: 活动数据、用户行为、宝物抓取统计

## 执行顺序与关键路径

### 阶段一: 地基搭建 (第 1-3 天)
- **执行**: [P1: 基础设施与项目脚手架]
- **并行任务**:
  - 初始化 Spring Boot 项目 (后端)
  - 初始化 React + Vite 项目 (前端)
  - 配置 Docker Compose 编排
- **里程碑**: 本地能通过 Docker Compose 启动空壳服务

### 阶段二: 核心开发 (第 4-8 天, 并行)
- **后端轨道**: [P2: 数据库设计] → [P3: 后端核心服务]
  - 数据库 Schema 设计与 Flyway 迁移
  - 游戏验证引擎 (物理计算)
  - 核心 API 端点
- **前端轨道**: [P4: 前端架构与游戏引擎集成]
  - React-Phaser 桥接层
  - 钩子物理模拟与碰撞检测
  - 基础 UI 页面
- **里程碑**: 前后端能独立运行游戏逻辑 (前端演示模式, 后端 API 可测试)

### 阶段三: 业务实现 (第 9-12 天)
- **执行**: [P5: 业务功能开发]
  - 积分系统 (账户、明细、排行榜)
  - 奖品系统 (配置、兑换、订单)
  - 后台配置管理接口
- **里程碑**: 完整的 MVP 流程可跑通 (游戏 → 积分 → 兑换)

### 阶段四: 加固与交付 (第 13-15 天)
- **执行**: [P6: 防作弊体系、测试与部署优化]
  - 多层防作弊机制
  - E2E 测试 (Playwright)
  - 性能优化与压力测试
  - 生产环境部署配置
- **里程碑**: 生产环境就绪

## 架构关键决策

### 并行开发策略
- **P3 和 P4 并行开发**: 通过定义好的 OpenAPI Spec (Swagger) 进行接口契约管理
- **前后端分离**: 前端可使用 Mock 数据先行开发,后端 API 就位后对接

### 防作弊策略
- **核心**: 所有关键操作 (抓取结果、得分) 必须在 P3 阶段定义的 `GameVerificationService` 中重放计算
- **多层防御**: 传输安全 → 会话控制 → 物理验证 → 行为分析 → 事后审计

### 状态管理策略
- **前端**: Zustand 管理全局状态 (用户、积分、UI), Phaser 内部状态自治
- **桥接**: Event Bus 实现 React ↔ Phaser 双向通信
- **后端**: Redis 缓存 (配置、会话) + PostgreSQL 持久化

## 风险与全局依赖

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| Phaser 物理效果与后端数学计算不一致 | 高 | P2 阶段明确定义物理参数, P6 阶段编写确定性测试 |
| WebSocket 连接在高并发下的稳定性 | 中 | P1 阶段引入 Redis Pub/Sub 做会话共享预备 |
| 前后端 API 接口变更导致对接困难 | 中 | 使用 Swagger/OpenAPI 规范, 接口变更版本管理 |
| 游戏性能不达标 (帧率 < 30fps) | 高 | P4 阶段使用对象池、纹理图集优化, P6 阶段性能压测 |

## 验收标准

### 功能验收
- [ ] 所有 Docker 服务正常启动且健康检查通过
- [ ] 完整游戏流程: 首页 → 关卡选择 → 游戏 → 结果 → 积分 → 兑换
- [ ] 游戏核心功能: 钩子摆动/发射/抓取/得分计算正常

- [ ] 奖品系统: 库存扣减/兑换记录/订单状态流转正确

### 质量验收
- [ ] 后端 API 覆盖率 > 80%
- [ ] 关键路径有集成测试覆盖
- [ ] E2E 测试覆盖主要用户流程
- [ ] 防作弊测试用例全部通过
- [ ] 生产环境部署脚本验证通过

- [ ] 游戏画面帧率 ≥ 30fps (移动端) / 60fps (桌面端)

- [ ] 支持同时在线用户数 ≥ 100 人
