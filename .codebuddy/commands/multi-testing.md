# Multi-Testing Command

测试多 Agent 协同工作流，使用国产模型完成测试策略设计和实施。

## 使用方法

```bash
/multi-testing <测试任务描述>
```

## 任务描述

**用户需求**: $ARGUMENTS

## 执行流程

### 阶段 1: 需求分析 [Mode: Analysis]

1. 调用 `requirements-analyzer` agent 评估需求完整性
2. 理解被测试的功能和测试目标

```
请调用 requirements-analyzer agent 分析以下测试需求：
$ARGUMENTS
```

### 阶段 2: 测试策略 [Mode: Strategy]

1. 调用 `test-analyzer` agent 设计测试策略
2. 获取至少 2 个测试方案
3. 等待用户选择一个方案

```
请调用 test-analyzer agent 设计测试策略：
需求: $ARGUMENTS
```

输出格式要求：
- 提供至少 2 个测试方案（工具选择、覆盖目标）
- 包含测试类型规划（单元、集成、E2E）
- 列出关键测试场景
- 包含覆盖率目标
- 等待用户选择方案后再继续

### 阶段 3: 测试实施 [Mode: Execute]

严格遵循批准的测试策略实施：

**单元测试**:
- 编写单元测试，确保 80%+ 覆盖率
- 使用适当的 mocking
- 测试边界条件和错误情况

**集成测试**:
- 测试 API 端点
- 测试数据库交互
- 测试服务间通信

**E2E 测试**:
- 测试关键用户流程
- 使用 Playwright 或类似工具
- 确保跨浏览器兼容性

在关键节点请求用户反馈。

### 阶段 4: 执行验证 [Mode: Verify]

1. 运行所有测试套件
2. 生成覆盖率报告
3. 分析测试结果

```
运行测试：
npm run test:unit
npm run test:integration
npm run test:e2e
npm run test:coverage
```

### 阶段 5: 质量审查 [Mode: Review]

1. 调用 `code-reviewer` agent 审查测试代码
2. 根据审查结果进行优化

```
请调用 code-reviewer agent 审查测试代码：
关注点: 测试质量、覆盖率、可维护性
```

### 阶段 6: 最终报告 [Mode: Report]

生成测试报告，包含：

- 测试覆盖率统计
- 通过/失败测试数量
- 发现的问题列表
- 性能测试结果（如有）
- 改进建议

## Agent 映射

| 阶段 | Agent | 模型 | 任务 |
|------|-------|------|------|
| Analysis | requirements-analyzer | glm-5.0 | 需求分析 |
| Strategy | test-analyzer | kimi-k2.5 | 测试策略设计 |
| Execute | (主对话) | (默认) | 测试实施 |
| Verify | (主对话) | (默认) | 执行测试 |
| Review | code-reviewer | kimi-k2.5 | 测试代码审查 |
| Report | (主对话) | (默认) | 生成报告 |

## 使用示例

```bash
# 为新功能编写测试
/multi-testing 为用户注册功能编写完整的测试套件

# 提升测试覆盖率
/multi-testing 提升订单模块的测试覆盖率到 85% 以上

# 创建 E2E 测试
/multi-testing 为购物车流程创建 E2E 测试
```

## 质量标准

### 测试覆盖率目标

| 测试类型 | 目标覆盖率 | 优先级 |
|---------|-----------|--------|
| 单元测试 | 80%+ | 高 |
| 集成测试 | 60%+ | 中 |
| E2E 测试 | 关键路径 | 高 |

### 测试质量检查清单

- [ ] 单元测试覆盖率达到 80%+
- [ ] 集成测试覆盖主要业务流程
- [ ] E2E 测试覆盖关键用户路径
- [ ] 测试命名清晰明确
- [ ] 测试独立且可重复运行
- [ ] 测试包含边界条件
- [ ] 测试包含错误情况
- [ ] Mock/Stub 使用恰当
- [ ] 测试执行速度快
- [ ] 无 flaky 测试

## 注意事项

1. **TDD 原则**：优先采用测试驱动开发
2. **测试独立性**：每个测试应该独立运行
3. **清晰命名**：测试名称应该描述测试内容
4. **避免 flaky**：避免不稳定、间歇性失败的测试
5. **及时更新**：功能变更时同步更新测试
6. **文档记录**：复杂测试逻辑需要注释说明

## 成功标准

- 测试策略设计合理
- 覆盖率达到目标要求
- 所有测试通过
- 无 flaky 测试
- 测试代码质量高
- 文档完善
