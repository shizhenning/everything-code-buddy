# OpenSpec 质量决策矩阵

本文档定义了在OpenSpec集成模式下的质量评估决策规则,用于确定计划是否可以进入执行阶段。

## 决策维度

### 维度1: 计划质量 (Plan Quality)

| 指标 | 权重 | 评估标准 | 分值 |
|------|------|----------|------|
| 目标清晰度 | 20% | 目标明确、可衡量、可达成 | 0-100 |
| 范围边界 | 15% | 输入输出明确、边界清晰 | 0-100 |
| 实施步骤 | 25% | 步骤完整、逻辑清晰、可执行 | 0-100 |
| 风险评估 | 15% | 风险识别完整、缓解措施合理 | 0-100 |
| 技术方案 | 25% | 方案可行、符合最佳实践 | 0-100 |

### 维度2: OpenSpec 完整性 (OpenSpec Completeness)

| 指标 | 权重 | 评估标准 | 分值 |
|------|------|----------|------|
| proposal.md 质量 | 20% | 目标、范围、验收标准完整 | 0-100 |
| design.md 质量 | 20% | 架构决策、技术选型明确 | 0-100 |
| specs/ 完整性 | 20% | 规格文件覆盖所有需求 | 0-100 |
| tasks.md 质量 | 20% | 任务粒度合理、优先级清晰 | 0-100 |
| 链接完整性 | 20% | 三层链接(前向、后向、映射表)完整 | 0-100 |

### 维度3: 任务可执行性 (Task Executability)

| 指标 | 权重 | 评估标准 | 分值 |
|------|------|----------|------|
| 任务粒度 | 30% | 3-10分钟/任务,独立可执行 | 0-100 |
| 依赖关系 | 25% | 依赖关系清晰,无循环依赖 | 0-100 |
| 验收标准 | 25% | 每个任务有明确验收标准 | 0-100 |
| 资源预估 | 20% | 时间预估合理,资源充足 | 0-100 |

## 质量决策阈值

### 综合得分计算

```
总分 = (计划质量 × 30%) + (OpenSpec完整性 × 40%) + (任务可执行性 × 30%)
```

### 决策规则

| 总分范围 | 决策 | 说明 |
|----------|------|------|
| 90-100 | ✅ 批准执行 | 高质量计划,可以立即执行 |
| 80-89 | ⚠️ 有条件批准 | 需要小幅改进,可执行 |
| 70-79 | ❌ 需要改进 | 需要重大改进,不能执行 |
| 0-69 | ❌ 拒绝 | 计划不完整,需要重新规划 |

### 单维度阈值

| 维度 | 最低分 | 说明 |
|------|--------|------|
| 计划质量 | ≥70 | 低于此分需要重新规划 |
| OpenSpec完整性 | ≥80 | 低于此分需要补充工件 |
| 任务可执行性 | ≥70 | 低于此分需要重新细化任务 |

## 快速检查清单 (P0检查项)

以下P0检查项必须全部通过才能批准执行:

### 计划质量 P0
- [ ] 目标明确且有可衡量的成功标准
- [ ] 范围边界清晰,不超出项目能力
- [ ] 实施步骤完整且逻辑连贯
- [ ] 技术方案可行且有实施路径

### OpenSpec P0
- [ ] proposal.md 包含目标、范围、验收标准
- [ ] design.md 包含架构决策和技术选型
- [ ] tasks.md 包含粒度任务列表(checkbox格式)
- [ ] 三层链接完整(前向、后向、映射表)
- [ ] 所有链接验证通过

### 任务可执行性 P0
- [ ] 所有任务可独立执行(无隐含依赖)
- [ ] 每个任务有明确的验收标准
- [ ] P0任务构成完整的关键路径

## 决策流程

```
开始
  ↓
生成计划
  ↓
检查P0项 (必须全部通过)
  ↓ 否 → 修复P0问题 → 重新生成计划
  ↓ 是
计算三个维度得分
  ↓
检查单维度阈值 (≥70/≥80)
  ↓ 否 → 改进最低分维度 → 重新评估
  ↓ 是
计算综合得分
  ↓
应用决策规则
  ↓
≥80分 → 批准执行
70-79分 → 改进后重新评估
<70分 → 重新规划
```

## 使用示例

### 示例1: 高质量计划

```
计划质量: 92分
- 目标清晰度: 95
- 范围边界: 90
- 实施步骤: 93
- 风险评估: 88
- 技术方案: 92

OpenSpec完整性: 95分
- proposal.md: 98
- design.md: 95
- specs/: 92
- tasks.md: 95
- 链接完整性: 95

任务可执行性: 90分
- 任务粒度: 92
- 依赖关系: 88
- 验收标准: 90
- 资源预估: 90

总分 = (92 × 0.3) + (95 × 0.4) + (90 × 0.3) = 27.6 + 38 + 27 = 92.6

决策: ✅ 批准执行 (92.6分)
```

### 示例2: 需要改进的计划

```
计划质量: 85分
OpenSpec完整性: 75分 (低于阈值80)
任务可执行性: 80分

总分 = (85 × 0.3) + (75 × 0.4) + (80 × 0.3) = 25.5 + 30 + 24 = 79.5

决策: ❌ 需要改进
原因: OpenSpec完整性低于阈值(75 < 80)
行动: 补充 specs/ 文件,完善链接验证
```

## 集成到工作流

### multi-plan Phase 4.5 集成

在Phase 4.5完成OpenSpec集成后,自动执行质量评估:

```javascript

const qualityAssessment = {
  planQuality: calculatePlanQuality(plan),
  openspecCompleteness: calculateOpenSpecCompleteness(changeName),
  taskExecutability: calculateTaskExecutability(tasksMd)
};

const totalScore = 
  qualityAssessment.planQuality * 0.3 +
  qualityAssessment.openspecCompleteness * 0.4 +
  qualityAssessment.taskExecutability * 0.3;

if (totalScore >= 80) {
  console.log("✅ 计划批准执行");
  // 提示用户运行 /multi-execute

  // 提供详细反馈
}
```

## 质量改进建议

### 改进计划质量
1. 使用SMART原则细化目标
2. 明确输入输出,定义边界条件
3. 拆分大步骤为小步骤
4. 识别更多风险并制定缓解措施
5. 参考最佳实践完善技术方案

### 改进OpenSpec完整性
1. 在proposal.md中添加详细验收标准
2. 在design.md中补充架构图和API文档
3. 在specs/中创建完整的规格文件
4. 使用task-refiner细化任务粒度
5. 运行validate-plan-links.js修复链接问题

### 改进任务可执行性
1. 将大任务拆分为3-10分钟的小任务
2. 明确标注任务间的依赖关系
3. 为每个任务添加明确的验收标准
4. 重新评估时间和资源预估

## 附录: 评分细则

### 目标清晰度 (0-100)
- 100: 目标明确,有多个可衡量的KPI
- 80: 目标明确,有可衡量的成功标准
- 60: 目标基本明确,成功标准不够具体
- 40: 目标模糊,难以判断是否达成
- 20: 目标不明确

### 任务粒度 (0-100)
- 100: 所有任务3-5分钟,可独立执行
- 80: 大部分任务3-10分钟,少量稍大
- 60: 任务粒度不均,有超15分钟任务
- 40: 多数任务超过15分钟
- 20: 任务太大,无法独立执行

### 链接完整性 (0-100)
- 100: 三层链接完整,验证通过
- 80: 三层链接存在,验证有小问题
- 60: 两层链接存在,一层缺失
- 40: 只有一层链接
- 20: 无链接
