# PRD需求提取 Skill (prd-requirements-extraction)

## 何时使用此Skill

在以下场景使用此Skill：

1. 分析PRD文档，需要提取结构化需求信息时
2. 为AI编码准备清晰的需求规范时
3. 建立需求依赖关系和优先级时
4. 准备进行架构影响分析之前

此Skill应被 `prd-analyzer` agent 调用。

## 如何工作

### 步骤1: 用户故事提取

从PRD中识别并格式化用户故事，使用标准格式：

```
作为 [角色]
我希望 [目标]
以便 [价值]
```

**提取示例**：

```markdown
## 用户故事

### US-001: 批量导入用户
**作为一个** 管理员
**我希望** 批量导入用户数据
**以便** 快速初始化用户库，提高运营效率

**验收标准**:
- 支持CSV和Excel格式
- 单次最多导入1000条记录
- 导入失败时显示具体错误信息
- 导入耗时不超过30秒

**优先级**: P0 (必须有)

### US-002: 批量导出用户
**作为一个** 管理员
**我希望** 批量导出用户数据
**以便** 进行数据分析和备份

**验收标准**:
- 支持CSV和Excel格式
- 支持按条件筛选导出
- 导出文件大小不超过10MB时3秒内完成
- 大文件导出显示进度条

**优先级**: P1 (应该有)

**依赖**: US-001
```

### 步骤2: 功能需求提取

识别并格式化所有功能需求，包含完整元数据：

```markdown
## 功能需求

### FR-001: 文件上传与解析
- **描述**: 支持用户选择CSV或Excel文件，解析并验证文件内容
- **优先级**: P0
- **验收标准**:
  - [ ] 支持拖拽上传
  - [ ] 支持点击选择文件
  - [ ] 文件大小限制为5MB
  - [ ] 解析错误时显示行号和错误详情
  - [ ] 验证必填字段
- **前置依赖**: 用户登录 (FR-100)
- **技术要求**:
  - 前端使用File API读取文件
  - 后端使用papaparse和xlsx库
  - 文件存储在云存储中
- **复杂度**: 中

### FR-002: 数据预览
- **描述**: 在导入前显示数据预览，允许用户确认数据正确性
- **优先级**: P1
- **验收标准**:
  - [ ] 显示前10条记录
  - [ ] 标记不符合格式的字段
  - [ ] 显示字段映射关系
  - [ ] 支持编辑预览数据
- **前置依赖**: FR-001
- **技术要求**:
  - 前端使用虚拟滚动优化性能
  - 后端分页返回数据
- **复杂度**: 中
```

### 步骤3: 非功能需求提取

识别并分类所有非功能需求：

```markdown
## 非功能需求

### 性能需求
- **NFR-PERF-001**: 单次导入1000条用户数据耗时不超过30秒
- **NFR-PERF-002**: 导出1000条用户数据耗时不超过3秒
- **NFR-PERF-003**: 页面加载时间不超过2秒
- **NFR-PERF-004**: 文件上传进度实时反馈

### 安全需求
- **NFR-SEC-001**: 文件上传需要用户认证
- **NFR-SEC-002**: 导出的数据仅限管理员权限
- **NFR-SEC-003**: 上传的文件必须扫描病毒
- **NFR-SEC-004**: 敏感字段（如密码）不允许导入导出

### 可用性需求
- **NFR-USAB-001**: 操作流程不超过3步完成
- **NFR-USAB-002**: 错误信息清晰易懂
- **NFR-USAB-003**: 支持键盘快捷键操作
- **NFR-USAB-004**: 提供操作帮助文档

### 兼容性需求
- **NFR-COMP-001**: 支持Chrome 90+, Firefox 88+, Safari 14+
- **NFR-COMP-002**: 支持移动端浏览器（iOS 14+, Android 10+）
- **NFR-COMP-003**: CSV文件支持UTF-8编码

### 可扩展性需求
- **NFR-SCAL-001**: 支持未来扩展导入更多数据类型
- **NFR-SCAL-002**: 导入导出任务可异步处理
```

### 步骤4: 业务规则提取

识别并格式化所有业务规则，使用IF-THEN格式：

```markdown
## 业务规则

### BR-001: 用户数据验证
- **IF** 用户名字段为空
  **THEN** 标记为错误，不允许导入
- **IF** 邮箱格式不正确
  **THEN** 标记为警告，允许用户决定是否导入
- **IF** 用户已存在（根据邮箱判断）
  **THEN** 跳过该记录或更新现有用户（用户可选）

### BR-002: 导入策略
- **IF** 导入文件超过1000条记录
  **THEN** 提示用户拆分文件或分批导入
- **IF** 导入过程中超过5条记录失败
  **THEN** 停止导入，显示失败列表
- **IF** 导入成功率低于80%
  **THEN** 要求用户确认后继续

### BR-003: 数据导出规则
- **IF** 导出数据超过10000条
  **THEN** 使用异步任务处理，完成后通知用户
- **IF** 导出条件查询结果为空
  **THEN** 提示用户并取消导出
```

### 步骤5: 需求依赖关系图

建立需求之间的依赖关系：

```markdown
## 需求依赖关系

```
FR-100 (用户登录)
    ↓
FR-001 (文件上传与解析)
    ↓
FR-002 (数据预览) ──→ FR-003 (数据导入)
                           ↓
                     FR-004 (导入结果展示)
```

**关键路径**: FR-100 → FR-001 → FR-003 → FR-004

**可并行开发**: FR-002 (与FR-001后端并行)
```

### 步骤6: 需求优先级矩阵

生成需求优先级矩阵：

| 需求ID | 需求描述 | 优先级 | 业务价值 | 技术复杂度 | 实现建议 |
|--------|----------|--------|----------|------------|----------|
| FR-001 | 文件上传与解析 | P0 | 高 | 中 | Sprint 1 |
| FR-003 | 数据导入 | P0 | 高 | 高 | Sprint 1-2 |
| FR-002 | 数据预览 | P1 | 中 | 中 | Sprint 2 |
| FR-004 | 导入结果展示 | P1 | 中 | 低 | Sprint 2 |

## 输出格式

最终输出为Markdown格式的 `01-需求规范.md`，包含以下章节：

```markdown
# 需求规范

## 1. 用户故事
(列出所有用户故事)

## 2. 功能需求
(列出所有功能需求，包含完整元数据)

## 3. 非功能需求
(分类列出所有非功能需求)

## 4. 业务规则
(列出所有业务规则)

## 5. 需求依赖关系
(依赖关系图和关键路径)

## 6. 需求优先级矩阵
(优先级分析表格)

## 7. 需求统计
- 用户故事: N 个
- 功能需求: N 个
- 非功能需求: N 个
- 业务规则: N 条
```

## 注意事项

1. **保持格式一致性**: 所有需求使用统一的格式和编号
2. **完整性检查**: 确保所有需求都已被提取，不遗漏
3. **清晰性**: 需求描述要清晰明确，避免歧义
4. **可测试性**: 每个需求都应该有可测试的验收标准
5. **可行性**: 评估需求的技术可行性，标注高风险需求
6. **优先级合理性**: 根据业务价值和技术复杂度合理设置优先级
