# /prd-analyze - PRD文档分析

**用途**: 系统化分析PRD文档，将业务需求转化为技术可执行的结构化规范，为AI驱动编码提供清晰指导。

## 何时使用

在以下场景使用此命令：

1. **需求开发阶段**：接收到新的PRD文档，需要系统化分析时
2. **需求优化阶段**：已有PRD需要深度分析和优化时
3. **技术方案设计**：需要评估需求对架构的影响时
4. **任务分解**：需要将PRD拆解为可执行的 开发任务时
5. **OpenSpec集成**：需要将PRD转换为OpenSpec格式时

## 工作流程

### 阶段1: 需求提取与结构化
调用 `prd-analyzer` agent 结合 `prd-requirements-extraction` skill：

- 提取用户故事（角色-目标-价值格式）
- 提取功能需求（ID、描述、优先级、验收标准、依赖）
- 提取非功能需求（性能、安全、可用性等）
- 提取业务规则（IF-THEN格式）

**输出**: 结构化需求规范文档

### 阶段2: 架构影响分析
调用 `prd-analyzer` agent 结合 `prd-architecture-analysis` skill：

- 评估需求对5个架构层次的影响（表现层、应用层、领域层、基础设施层、跨横切关注点）
- 识别架构变更类型（新增、修改、重构、删除、迁移）
- 进行技术选型评估
- 识别复用机会

**输出**: 架构影响评估报告

### 阶段3: Skills Gap Analysis (新增)
调用 `prd-analyzer` agent 结合 `prd-skills-gap-analysis` skill：

- 分析项目技术需求（前端、后端、DevOps、领域特定）
- 扫描 `.codebuddy/skills` 目录，盘点现有技能
- 对比需求与现有技能，识别技能缺口
- 为技能缺口评分（关键、重要、可选）
- 生成技能补充建议和实现路线图

**输出**: 技能缺口分析报告和补充建议

### 阶段4: 风险评估
调用 `prd-analyzer` agent 结合 `prd-risk-analysis` skill：

- 识别技术风险、业务风险、进度风险、外部风险
- 使用5x5风险矩阵评估（概率×影响）
- 为每个风险制定缓解策略

**输出**: 风险评估矩阵和缓解计划

### 阶段5: UI/UE分析
调用 `prd-analyzer` agent 结合 `prd-ui-ue-analysis` skill：

- 分析界面布局与结构
- 设计交互流程
- 定义组件级UI要求
- 建立视觉设计规范
- 设定性能体验要求
- 评估无障碍访问
- 规划多端适配方案

**输出**: UI/UE设计规范

### 阶段5: (可选) OpenSpec集成
调用 `openspec-new-change` agent，将分析结果转换为OpenSpec格式：

- 生成能力规格（Capability Spec）
- 记录设计决策（Design Decisions）
- 创建任务列表（Task List）

**输出**: OpenSpec artifacts

## 使用方式

```bash
/prd-analyze
```

### 交互式分析流程

该命令提供完整的交互式对话机制，会在分析过程中与用户进行多轮交互：

#### 第1步：选择分析模式
```
请选择PRD分析模式：
1. 创建新的PRD（从头开始）
2. 分析已有PRD（优化现有需求）
```

#### 第2步：PRD内容输入

**选项1：创建新的PRD**
```
请描述你的产品需求，我可以帮你：
- 从零开始构建PRD
- 补充和完善需求描述
- 梳理业务逻辑和用户场景
```

系统会通过多轮对话引导用户：
- **业务背景**：产品目标、目标用户、核心价值
- **功能需求**：核心功能列表、优先级排序
- **非功能需求**：性能、安全、可用性要求
- **约束条件**：技术栈限制、时间预算、团队能力
- **参考系统**：竞品分析、现有系统集成

**选项2：分析已有PRD**
```
请提供PRD文档内容：
1. 粘贴PRD文本内容
2. 指定PRD文件路径
3. 提供PRD文档链接（URL）
```

#### 第3步：选择分析维度
```
请选择需要分析的内容（可多选）：
□ 需求提取与结构化
□ 架构影响分析
□ Skills缺口分析（对比现有skills）
□ 风险评估
□ UI/UE分析
□ OpenSpec集成（生成技术规格）
```

用户可以：
- 全选：进行完整分析
- 部分选择：针对特定维度深入分析
- 系统建议：根据PRD类型推荐分析维度

#### 第4步：分析过程中的交互澄清

在分析过程中，当遇到模糊或不完整的需求时，系统会主动澄清：

**需求澄清示例**：
```
❓ 澄清问题

在分析"批量导入用户"功能时，我发现以下信息不明确：

1. **文件格式限制**：
   - 问题：是否只支持CSV和Excel？是否需要支持JSON？
   - 预设选项：
     A. 仅CSV和Excel
     B. CSV、Excel、JSON
     C. 自定义格式

2. **数据量限制**：
   - 问题：单次导入的最大数据量是多少？
   - 预设选项：
     A. 1000条
     B. 5000条
     C. 无限制（建议分批）

3. **冲突处理策略**：
   - 问题：当导入数据与现有数据冲突时如何处理？
   - 预设选项：
     A. 跳过冲突记录
     B. 覆盖现有数据
     C. 用户选择

请选择或输入自定义答案：
```

用户可以：
- 选择预设选项
- 输入自定义答案
- 跳过此问题（使用默认假设）

#### 第5步：分析结果确认与优化

每完成一个分析阶段，会展示结果并征求用户反馈：

```
✅ 需求提取完成

提取到以下内容：
- 用户故事：5个
- 功能需求：12个
- 非功能需求：8个
- 业务规则：6条

是否需要调整？
□ 确认继续下一阶段
□ 调整优先级
□ 添加遗漏的需求
□ 修改描述不准确的需求
```

#### 第6步：生成最终报告

```
📊 PRD分析完成！

已生成以下文档：
✅ 01-需求规范.md
✅ 02-架构影响评估.md
✅ 03-Skills缺口分析.md
✅ 04-风险评估.md
✅ 05-UI-UE设计规范.md
✅ 06-技术建议.md

下一步操作：
□ 查看完整报告
□ 继续生成OpenSpec artifacts
□ 导出为JSON格式
□ 调用 /plan 进行详细规划
□ 调用 /tdd 生成测试用例
```

## 与其他命令集成

- **/plan**: 使用PRD分析结果进行详细实现规划

## 示例输出片段

### 需求规范示例

```markdown
## 用户故事
US-001: 作为一个管理员，我需要批量管理用户，以便提高运营效率

## 功能需求
FR-001: 批量导入用户
- 优先级: P0 (必须有)
- 验收标准:
  - 支持CSV和Excel格式
  - 单次最多导入1000条
  - 导入失败时显示具体错误信息
- 依赖: 用户管理模块 (UM-001)
```

### UI/UE分析示例

```markdown
## 组件定义: UserBatchImport

### Props
```typescript
interface UserBatchImportProps {
  onImportSuccess: (count: number) => void
  onImportError: (errors: ImportError[]) => void
  maxFileSize?: number
  allowedFormats?: ('csv' | 'xlsx')[]
}
```

### 交互流程
1. 用户点击"选择文件"按钮 → 触发文件选择器
2. 选择文件 → 解析并验证格式 → 显示预览
3. 确认导入 → 上传处理 → 显示进度条
4. 完成导入 → 显示成功通知 + 导入数量
5. 部分失败 → 显示错误列表 + 高亮失败行

### 无障碍要求
- 文件输入框需要 aria-label
- 上传进度需要 role="progressbar"
- 错误信息需要 role="alert"
```

## 最佳实践

1. **提供完整PRD**: 包含业务背景、目标用户、功能描述、非功能需求
2. **明确优先级**: 标注P0/P1/P2以指导实现顺序
3. **附上线框图**: 帮助UI/UE分析更准确
4. **指定约束条件**: 性能要求、技术栈限制、合规要求
5. **参考现有系统**: 说明与现有系统的关系和集成点

## 注意事项

- 分析结果的准确性依赖于PRD的质量和完整性
- UI/UE分析是前端开发的关键，建议重点关注
- 风险评估需要结合团队实际能力判断
- OpenSpec集成是可选功能，适合复杂项目
- 分析结果可以迭代优化，不必一次性完美
